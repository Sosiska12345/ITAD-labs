# Лабораторная работа №2: Ingestion и слой raw в локальном Data Lake

Репозиторий содержит настроенную и полностью исправленную кодовую базу для развёртывания локальной инфраструктуры захвата данных (Ingestion) и формирования сырого слоя (`raw`) архитектуры Medallion.

##  Архитектурный контур и изменения стек-технологий

В ходе выполнения работы и устранения замечаний ревью, исходная конфигурация была адаптирована под актуальные требования курса и особенности операционной системы Linux:
* **S3-совместимое хранилище (Стек):** Вместо MinIO развёрнуто легковесное и производительное хранилище **SeaweedFS** (порт S3 API: `8333`, порт Filer UI: `8888`), использующееся в текущих демо-каркасах курса. Логика работы с S3 API (`S3Hook` в Airflow и `httpfs` в DuckDB) осталась неизменной.
* **Декларативная конфигурация:** Все параметры датасета (`DATASET_SLUG`, `SOURCE_FILENAME`, `RAW_BUCKET`, `SOURCE_URL`) полностью вынесены в файлы окружения `.env` и проброшены внутрь Docker Compose. Жёстко зашитые (hardcoded) дефолтные значения устранены по всему проекту.

##  Сетевой Troubleshooting и локальный Fallback-сценарий

При тестировании сетевого скачивания датасета `hour.csv` напрямую из репозитория GitHub по HTTP-ссылке была зафиксирована критическая ошибка `requests.exceptions.ConnectionError (NameResolutionError)` на этапе проверки `HttpSensor`.

### Причины сбоя:
1. **Конфликт VPN и Docker Bridge:** Активный VPN-клиент в Arch Linux изменяет системные DNS-маршруты. Виртуальный мост Docker (`docker0`) теряет связь с внешними шлюзами, из-за чего контейнеры Airflow перестают резолвить внешние домены (включая `githubusercontent.com`). Простое отключение VPN не сбрасывает кэшированные маршруты в ядре Linux без полной перезагрузки сетевого демона Docker (`systemctl restart docker`).
2. **Фильтрация DPI / ТСПУ провайдеров:** Домен `://githubusercontent.com` периодически подвергается скрытой фильтрации со стороны магистральных интернет-провайдеров РФ на оборудовании ТСПУ (Deep Packet Inspection), блокируя прямые запросы из консольных утилит и контейнеров без VPN.

### Реализация отказоустойчивости (Шаг 6 методички):
Для обеспечения стабильности пайплайна был активирован штатный **сценарий ручного Fallback**:
* Исходный стабильный снимок датасета Bike Sharing (`hour.csv`) скопирован локально в корень проекта.
* Разработан автономный код DAG (`load_to_raw_fallback`), который динамически определяет путь к папке дагов с помощью встроенных макросов Airflow (`conf.get("core", "dags_folder")`) и считывает файл напрямую через внутренний мост томов Docker (`/opt/airflow/dags/`).
* Пайплайн успешно выполнил все ключевые требования ЛР №2: **идемпотентность** (проверка `s3_hook.check_for_key` предотвращает дубликаты) и **партиционирование** (данные улетают в бакет по строгому пути `s3://raw/hour_data/ingested_on=2026-09-16/hour.csv`).
